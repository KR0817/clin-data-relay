# Confirmed test seams

The first implementation will test behavior through these public HTTP seams:

1. **Centre isolation:** a centre A user cannot read or review centre B candidates.
2. **Candidate lifecycle:** a candidate begins `candidate` and can become `human_confirmed` or `rejected`; all decisions remain visible in the audit feed.
3. **Transfer guard:** only a `human_confirmed` candidate can create a transfer request, and the request is always `simulation` while the EDC adapter is disabled.
4. **Image provenance:** every accepted candidate retains the source-file hash, OCR engine version, Kimi model/schema version, and reviewer identity.

5. **Adapter readiness:** the public readiness endpoint must report that the EDC write path is disabled unless a separately validated adapter is introduced; a local sandbox alone never enables writes.
6. **Transfer-package integrity:** each simulated transfer exposes a deterministic SHA-256 for the reviewed value package and records that hash in the public audit feed.
7. **Sandbox launcher:** the public PowerShell launcher must locate Docker's CLI and its credential helpers even when it is run from a pre-installation PowerShell session whose PATH has not refreshed.
8. **Release integrity:** the public sandbox launcher must refuse to build when the official LibreClinica 1.4.0 WAR is absent or its SHA-256 differs from the pinned release value.
9. **Local OCR candidate path:** an attested synthetic image can produce local-OCR candidates through a public endpoint, with the local engine version and a `local_ocr` audit event; no Kimi request occurs.
10. **Sandbox application surface:** a started sandbox must return from its root route and redirect the protected main menu to the local login route; a container that merely exposes Tomcat is not sufficient.
11. **Versioned field mapping:** every candidate-creation route must reject a field/event combination absent from the synthetic CRF mapping; the active mapping ID and version must be visible through health status and candidate provenance.
12. **Frozen transfer export:** a simulated transfer must persist and expose the canonical package that produced its SHA-256, independently recompute the digest, preserve centre isolation, and explicitly audit every blocked submit attempt while the adapter is disabled.
13. **Idempotent transfer receipt:** creating a transfer with the same bounded idempotency key must replay the original record without duplicating it; reuse for a different candidate must fail, and the immutable simulation receipt must be downloadable with an independently verifiable SHA-256.
14. **Simulation reconciliation ledger:** users must see only authorised-centre transfer states; a blocked submission must become a structured failure, a failed request may be explicitly requeued with a cumulative retry count, and only a reviewer role may record an immutable audit event for manual reconciliation. Frozen packages and creation receipts must not be rewritten by these state changes.
15. **Local check-sheet ingestion:** an attested synthetic laboratory check-sheet may be OCR-processed locally from common `field result reference-range unit` rows; only fields confirmed by the versioned workbook-header mapping may be persisted as reviewable companion candidates, unmapped codes may be skipped only when at least one mapped result remains, an exact source/event replay must reuse the previously persisted candidates without rerunning OCR, and neither Kimi nor the Authority EDC may be called.
16. **Chinese direct-identifier gate:** the installed default local OCR runtime must use the project-pinned `chi_sim+eng` language data and reject a synthetic regression image containing a Chinese direct-identifier marker before creating any candidate.
17. **Mapping diagnostics:** the local OCR endpoint must distinguish an unknown event from an unknown field, while the browser restricts event selection to the currently mapped synthetic visits.
18. **Local de-identification draft:** an authorised centre user may create an authenticated, locally redacted derivative from an uploaded synthetic direct-identifier fixture; the API returns marker categories but never identifier values or original OCR text, the derivative preview is centre-isolated and non-cacheable, and local OCR must reject that derivative until a user explicitly attests that the redaction preview was reviewed. Confirmation creates no clinical value; it only allows the derivative to enter the existing candidate workflow.
19. **Conservative Chinese table fallback:** when plain OCR yields no mapped English field codes, the local OCR endpoint may use a versioned, exact-label Chinese laboratory alias map plus word coordinates from a preprocessed de-identified derivative. It may persist only unambiguous codes already allowed by the active CRF mapping, must skip conflicts and percentage/count ambiguities, and must retain the structured extractor version in candidate provenance.
20. **Inline reviewer interaction:** accept, edit, reject and manual reconciliation actions must open an in-page panel that requires a bounded reason or note, exposes an edited-value input only for edit, and never depends on a browser-native prompt. Opening and cancelling the panel must not change candidate state or create an audit event; reviewer-role enforcement remains server-side.
21. **Confirmed companion-data view and role simplification:** accepted or edited candidates must be visibly separated from the review queue and rendered from their persisted `final_value` plus reviewer metadata without overwriting OCR input. Only site investigators and the central data manager may authenticate; legacy entry-only accounts must remain inactive while their historical usernames remain available for audit provenance.
22. **Adapter-drift guard:** a queued transfer can be submitted only when its frozen mode and target match the currently configured adapter. Enabling LibreClinica must leave all historical simulation requests queued and untouched, make no network call for them, and allow a separate target-specific live request to be created.
23. **Kimi multimodal hybrid extraction:** the browser's single-page batch flow may call Kimi only for a confirmed de-identification derivative. The request must contain that derivative, bounded local OCR evidence and only uploadable headers from the active event's versioned CRF dictionary, use strict structured output, block identifier markers in text/TSV, and persist agreement/conflict/fallback provenance. A Kimi failure must preserve mapped local candidates without exposing provider error text, while no model output may bypass human review or write the Authority EDC.

No test will query internal database tables directly. The user approved continued implementation without additional confirmation on 2026-08-08; the seams above are therefore confirmed only for the synthetic-data MVP and its local sandbox.
