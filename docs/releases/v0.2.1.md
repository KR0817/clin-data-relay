# ClinData Relay v0.2.1

This is the first downloadable OSI-approved open-source release of ClinData
Relay. The repository and first-party portable bundles are licensed under
`AGPL-3.0-only`.

Version `v0.2.0` remains a source-only tag: its clean Windows build exposed an
undeclared `tessdata_fast` prerequisite. Version `v0.2.1` fixes that issue with
a bounded, digest-verified preparation step pinned to an immutable upstream
commit.

## Highlights

- Human-reviewed report-to-candidate workflow with local OCR and an optional
  OpenAI-compatible Kimi endpoint.
- Docker-free Windows Lite archive for local recognition, review and Excel
  export.
- Chinese and English project documentation, architecture diagram and a
  reproducible two-minute demo.
- Corresponding-source notice, standalone SHA-256 checksum and black-box
  verification report distributed with the Windows archive.
- Public benchmark protocol for comparing local OCR with OCR plus a model; no
  benchmark results or clinical-performance claims are included yet.

## Safety boundary

This release is a research prototype validated with synthetic fixtures. It is
not a validated EDC or a production clinical deployment. OCR and model outputs
remain candidate values requiring human review. LibreClinica remains the
authority record when that optional adapter is used. Do not process real
participant material without protocol, ethics, privacy, security, data-flow,
software-validation and institutional approvals.

## Windows Lite assets

- `ClinicalReportExtractorLite-windows-x64.zip`
- `ClinicalReportExtractorLite-windows-x64.sha256`
- `ClinicalReportExtractorLite-windows-x64.verification.json`

The archive is unsigned. Verify its SHA-256 value before extraction. The
verification report records the synthetic black-box checks performed during
the build.

## Known limitations

- Central PostgreSQL and managed institutional identity remain fail-closed and
  are not composed into the production HTTP runtime.
- The Windows binary is not code-signed.
- Clinical validation, threat-model review, backup/restore drills and
  institution-owned operations remain required before real use.
- `CITATION.cff` contains no DOI until the repository owner completes an
  external archival deposit.
